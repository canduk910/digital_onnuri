## 1번 과제 — verify_build.py CI 편입 (기록)

### 조사가 드러낸 것: 문제가 생각보다 컸다

막는 것은 `verify_build.py` 하나가 아니었다. **`build_index.py`(18·82행)도 같은 원본을 읽는다.**
즉 원본이 없으면 검증만 막히는 게 아니라 **`index.html` 을 재생성할 수 없다.**

그리고 더 중요한 것 — **92건 토큰 검사는 "index.html 이 build_index.py 산출물임"을 지키지 못한다.**
목록에 적어 둔 토큰이 있나 없나를 볼 뿐이라, 아무도 적지 않은 자리에서 소스와 산출물이 갈리면 조용히 통과한다.
**직접 변조 실험으로 확인했다**:

| 변조 | D-F1 92건 | 재빌드 바이트 비교 |
|---|---|---|
| 빌더의 출력 문구만 고치고 재빌드 누락 | 통과(못 잡음) | **EXIT=1 (잡음)** |
| 데이터 내용만 고치고 재빌드 누락(개수 불변) | 통과(못 잡음) | **EXIT=1 (잡음)** |

2026-08-18 파비콘 사고가 잡힌 것은 **사고 뒤에 (h) 검사를 새로 만들어 넣었기 때문**이지
검사가 원래 그 층을 덮어서가 아니다. 다음 사고는 아직 아무도 적지 않은 토큰에서 난다.

### 방안 선택 — 조사 권고를 따르지 않았다

조사는 "원본에서 뽑은 픽스처 + `index.html` 로부터 재구성"(+40 KB)을 권했다. **택하지 않았다.**

| | 조사 권고 (d) | 채택 (a) |
|---|---|---|
| 저장소 증가 | +40 KB | **+2,540 KB**(직접 측정) |
| 새 코드 | 스크립트 2개 | **0줄** |
| 순환 의존 | 있음 — manifest 를 `index.html` 에서 가져온다 | 없음 |
| `manifest 라인 불변` 검사 | **자기 자신 비교(항등식)** | 유효 |

두 가지가 결정했다.

**①순환과 그것을 지키는 게이트.** (d)는 sha256 게이트가 반드시 필요한데, 그 게이트는 나중에 누가
"어차피 같은 값"이라며 정리할 수 있다. ADR-21 때 `ProbeEndpoint` 주석을 믿고 정리했다가 robots 감시가
**허용 방향으로 조용히 망가진** 것과 같은 유형이다. 게다가 (d)에서는 검사 하나가 항등식이 된다.

**②검증기를 고치는 것 자체가 이 파일의 사고 이력이다.** 2026-08-12~18 에 라인 인덱스가 밀려
`verify_build.py` 가 **6일간 죽어 있었다.** (a)는 검증기를 한 줄도 안 고친다.

비용은 감당할 만하다 — 2.5 MB 는 한 번 넣으면 다시 바뀌지 않는 불변 파일이고, 이 저장소는
이미 **실수로 커밋된 빌드 산출물 54 MB**(jar 43.9 · terraform provider 9.8)를 지고 있다.

### 검증 수치를 직접 재서 조사를 정정했다

적대적 검증이 "(a)는 +8 KB — git 이 `index.html` 에 델타 압축한다"고 주장했다. **재현되지 않았다.**
`--no-hardlinks` 클론 + `gc --aggressive` 전후로 재니 **+2,540 KB** 이고,
블롭은 `3,093,802 B`로 **델타 없이** 저장된다(`deltabase=0000…`). 그래도 결론은 (a)다 —
검증의 수치는 틀렸지만 (d)의 순환 지적은 옳았고, 그 둘을 함께 놓으면 (a)가 남는다.

## 2번 과제 — CI 게이트 (기록)

### 조사 전제 하나가 틀렸고, 그것이 설계를 바꿨다

조사는 "`pages` 는 `backend/tools/**` 를 배포하지 않는다"를 권고의 세 기둥 중 하나로 삼았다.

직접 확인했다:

| URL | 응답 |
|---|---|
| `/backend/tools/nightly_update.py` | 200 · 65,977 B |
| `/CLAUDE.md` | 200 · 186,947 B |
| `/index.html.bak-20260806` | 200 · **4,150,904 B** |

저장소가 공개라 새로 노출되는 것은 없다(GitHub 에서 어차피 보인다). 그러나 **1번 과제에서
넣은 4.1 MB 원본이 매 배포 아티팩트에 올라가고 있었다** — 내가 만든 것이라 함께 처리했다.
업로드 전에 지운다. 노출 차단이 아니라 아티팩트 축소다.

### 설계 — 조사 권고를 절반만 따랐다

**따른 것**: 게이트를 `needs` 로 같은 런 안에 둔다(`workflow_run` 은 엉뚱한 커밋을 배포할
위험이 있고, 문서만 고친 커밋 20%는 tools-ci 런 자체가 안 생겨 트리거를 못 받는다).
게이트 내용은 **프론트 정적 계약 91건 하나**로 한정한다.

**따르지 않은 것**: 조사는 재사용 워크플로(`checks-frontend.yml`) 신설을 권했다.
적대적 검증이 지적한 대로 **호출자가 pages 하나뿐이라 사본 문제가 애초에 없다** —
파일 참조 결합만 늘린다. `pages.yml` 안에 잡으로 직접 뒀다.

**배치 테스트를 게이트에 넣지 않은 판단은 유지했다.** Pages 가 그 파일을 서빙하기는 하지만
**실행하는 것은 00:30 서버 배치**이고 그 경로는 Actions 를 지나지 않는다. 여기 묶으면
초록의 뜻이 "배포된 것이 검사됐다"가 아니라 "관계없는 것도 검사했다"가 된다.

### 검증 — 세 갈래를 라이브에서 확인했다

| 경로 | 확인 |
|---|---|
| 정상 커밋 | checks success(10초) → deploy success(14초). 총 +약 14초 |
| **계약을 깬 커밋** | checks **failure** · deploy **skipped** · **라이브 title 불변** → 즉시 revert |
| **탈출구**(`skip_checks=true`) | checks **skipped** · deploy **success** |

가운데 것을 실제로 해 보지 않았으면 "게이트를 걸었다"는 말만 남았을 것이다.
`needs` 만 쓰면 checks 가 skipped 일 때 deploy 도 함께 스킵되므로
`needs.checks.result == 'success' || == 'skipped'` 를 명시해야 탈출구가 산다 — 그것도 확인했다.

| | 실측 |
|---|---|
| 바깥에서 쓰는 것 | **3종 4회** — `el` 2 · `mapObj` 1 · `mapReady` 1 |
| 바깥이 쓰는 것 | **2곳** — `initSplit` · `initVSplit` |

허브가 얽힌 후보(브랜드 팝업 `state` 16회, 데이터 소스 26회, 즐겨찾기 `KEEP_INFO_ONCE` 쓰기)를
손대기 전에, pano 로 한 번 통한 주입 계약이 **두 번째로도 통하는지 state 위험 없이** 확인하는 자리다.

`merchants.html` 1,910 → **1,849줄**. 1·2단계와 합쳐 2,638 → 1,849 (**−29.9%**).

### 순수 이동이 아니다 — 한 가지를 바꿨다

`pagewidthchange` 청취자를 **모듈 최상위에서 `init()` 안으로 옮겼다.** 적대적 검증이 잡은 것이다.

원래는 스크립트가 평가되는 순간 등록됐는데, 외부 파일이 되면 그 시점이 `attach()` 보다 앞선다.
그때 폭 토글이 발화하면 `isMapReady` 가 아직 `null` 이라 **TypeError** 가 난다.
`init()` 안에서 등록하면 attach 이후가 보장된다. 대가는 "`init` 전에는 폭 토글에 반응하지 않는다"
인데 boot 이 곧바로 부르므로 실사용 차이가 없다.

### 이 동작을 덮는 테스트가 **하나도 없었다**

검증이 지적했고 사실이었다 — 드래그·`localStorage`·키보드·더블클릭 초기화 어느 것도
`grep` 0건이었다. 옮기면서 함께 만들었다.

| 층 | 추가 |
|---|---|
| 정적(CI) | 연결·순서·사본 부재·게터·**허브 미접촉**·청취자가 init 안 — 6건 |
| 렌더(로컬) | 드래그·저장·키보드·더블클릭 초기화·`pagewidthchange` → 지도 resize — 6건 |

**변조 3종 전부 EXIT=1**: 청취자를 모듈 최상위로 되돌림 / 지도를 값으로 받음 / `merchants.html` 에 사본 부활.

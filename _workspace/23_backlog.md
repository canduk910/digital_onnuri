## A. 지금 고치면 되는 것

전부 직접 재서 확인했다. 하나같이 작지만 **A1·A2 는 사고 때 드러나는 종류**라 위에 뒀다.

### A1. `DEPLOY.md` 의 `run.sh` 정본이 실제 서버와 다르다 — 그대로 복사하면 배치가 죽는다
`확인: 실측(서버 run.sh 30줄 대조)` · `크기: 작다`

문서의 "정본" 블록에 **없는 것**이 다섯이다. 서버에는 2026-08-23 · 09-01 에 하나씩 들어갔는데
문서는 8월 22일 상태에 멈춰 있다.

| 없는 줄 | 없으면 |
|---|---|
| `export PATH=/opt/node20/bin:$PATH` | 시스템 node v12 를 집어 **단계 D 스킵** |
| `export APP_BASE_URL` · `APP_ADMIN_KEY` | **단계 E(카나리아) 스킵** |
| `export OPENAI_API_KEY` (문서는 대신 `--skip-rag`) | **단계 C 스킵** |
| `export SURVEY_OUT_DIR` | 리포트가 기본 위치로 흩어진다 |
| `git checkout -- data/merchants …` | 산출물이 남은 순간 `pull` 실패 → `set -e` 로 **배치 전체 사망** |

마지막 줄은 2026-09-01 에 실제로 겪은 사고다(변경 이력에 기록됨). 문서만 보고 서버를 다시
세우면 **여섯 단계 중 셋이 조용히 안 돌고, 언젠가 전부 죽는다.**
고치는 법: 서버의 실제 `run.sh` 를 비밀값만 가려 문서에 그대로 옮긴다.

### A2. `bootstrap.sh` 가 폐기된 브랜치를 클론한다 — 새 서버 구축이 즉사
`확인: 실측(bootstrap.sh:5,10,32)` · `크기: 작다`

```
BRANCH="${BRANCH:-feat/backend-scaffold}"
git clone -b "$BRANCH" "$REPO_URL" "$WORKDIR"
```

`feat/backend-scaffold` 는 **2026-08-12 단일 브랜치 통합 때 폐기**됐다(ADR 및 변경 이력).
5행의 안내 `curl` 주소도 같은 브랜치를 가리킨다. 재해 복구·서버 이전 때만 쓰는 파일이라
평소에는 아무도 실행하지 않아 **정확히 필요한 순간에 실패한다.** `main` 으로 바꾸면 끝난다.

### A3. 배포 직후 회귀 기준값이 낡았다
`확인: 라이브 실측` · `크기: 작다`

| DEPLOY.md | 실제(2026-09-05) |
|---|---|
| 적재 `66,211` 건 | **79,800** |
| 개포동 `145` | 145 ✓ |
| 팔달구 `1241` | **1259** |

배포 직후 대조가 목적인 값인데 두 개가 틀리면, 다음 사람은 **정상인데 실패로 읽거나
아예 안 보게 된다.** 가맹점은 매일 배치가 갱신하므로 "그날의 값"을 적는 방식으로 바꾸거나,
변동이 적은 개포동 같은 값만 남기는 편이 낫다.

### A4. `.env.example` 에 관리자 키 항목이 없다
`확인: 실측(grep 0건)` · `크기: 작다`

`APP_ADMIN_KEY`(배치 단계 E)·`APP_ADMIN_PASSWORD`(제보 관리자 페이지)가 예시에 없다.
값은 당연히 비워 두되 **키 이름은 있어야** 새 서버에서 빠뜨리지 않는다.

### A5. README 곳 수가 낡았다
`확인: 실측` · `크기: 작다`

온라인 `30곳` → **31곳**, 가맹점 `78,000여 곳` → **79,800**.

### A7. CI 스텝 이름의 건수가 낡았다
`확인: 실측` · `크기: 작다`

## C. 사람이 결정할 것

내가 정할 수 없는 것들이다. 재료는 다 모아 뒀다.

### C1. 허브(`state`·`SNAP`·`refresh`)를 해체할 것인가
merchants 는 1,552줄에서 멈췄다. 남은 후보의 결합도는 `22_structural_run.md` 에 실측표로 있다.
허브를 정말 풀려면 **상태 저장소 + 구독**으로 바꾸는 설계 변경이 되고, 그건 페이지 동작을
바꾸는 일이라 사람의 결정이 필요하다. 22 문서에 "ADR 감"이라 적어 놓고 ADR 은 만들지 않았다.

### C2. 지도 범위가 시도를 대체하게 할 것인가
2026-09-04 에 "아침 판단으로 남긴다(아래 제안 참조)"고 적었는데 **가리킨 「제안」 절이
문서에 없다.** 현재 동작은 `region AND bounds` 이고, 화면이 `지도 범위 · 서울 N곳` 으로
기준을 밝혀 거짓은 아니다. 다만 "보이는 것을 검색한다"는 멘탈 모델과는 어긋나 있다.

### C3. 배포 게이트를 어디까지 넓힐 것인가
2026-09-05 에 Pages 에 게이트를 붙였지만 **거기 걸린 것은 정적 계약 158건 하나**다.

| 레인 | 게이트 |
|---|---|
| Pages(프론트) | 정적 계약 158건 ✓ |
| backend-ci(앱 배포) | `gradlew test` 만 — 정적·D-F1 은 안 지난다 |
| tools-ci(배치·채록) | **게이트 아님**(사후 알림, 문서에 명시) |
| 서버 야간 배치 | 게이트 없음 — 00:30 에 스스로 `git pull` |

렌더 113 · 스모크 · 실동작 45경로 · 스타일 대조는 **어느 워크플로에도 없다**(브라우저가 필요해서).
지도 절은 원격에서 어차피 스킵되므로 *지도 제외 렌더 + 스모크만* 넣는 절충이 가능하다.
배치 레인은 저장소 밖 `run.sh` 를 고쳐야 해 성격이 다르다.

### C4. 채록 델타를 읽는 리듬을 만들 것인가
B2 와 짝이다. 주 1회 사람이 리포트를 보는 절차를 두거나, 노이즈를 줄여

## E. 문서가 코드와 어긋난 것

**E1 은 위험 방향이 나쁘다** — 다음 사람이 문서를 정본으로 믿고 코드를 "고치면" 동작이 바뀐다.

### E1. ADR-7 이 코드와 정면으로 어긋난다
`확인: 실측` · `크기: 작다`

```
ADR-7  : bounds 활성 시 시도 무관 전 지역 검색 — API는 region 파라미터 생략
실제    : regionParams() { var p = { region: state.sido }; … if (LIST_BY_MAP) p = assign(p, b); }
```

2026-08-12 "뷰포트 자동 지도" 커밋이 `bounds` 를 **추가 AND** 로 바꾸며 대체 의미를 폐기했고
그 사실은 변경 이력에 있다. 그런데 **ADR 은 안 고쳤다.** ADR-4 는 `폐기`, ADR-11 은 `부분 개정`
표기를 갖고 있는데 ADR-7 만 옛 상태다. 개정 표기 한 줄이면 닫힌다.

### E2. ADR-10 이 "판단 필요"에 멈춰 있다
`확인: 실측` · `크기: 작다`

`재평가 시점 도래(2026-09-04)` · `유예를 계속할지 판단이 필요하다` 로 끝난다.
실제로는 1~3단계가 끝나 2,638 → 1,552줄(−41%)이 됐다. "유예 종료 — 남은 것은 허브"로
상태를 갱신하면 닫힌다(C1 과 함께 처리하면 자연스럽다).

### E3. ADR-12 가 "비스트리밍"이라 적혀 있다
`확인: 실측` · `크기: 작다`

`비스트리밍 수신 후 청크 SSE(OpenAI 스트림 파싱 복잡도 회피)` 로 적혀 있으나,
2026-08-11 에 실스트리밍(`chatStream`)으로 바뀌었다.

### E4. `19_online_probe.md` 1·2절 표가 대체됐는데 남아 있다
`확인: 훑기가 지목 — 미확인` · `크기: 작다`

1절 실현성 표의 "불가/차단"으로 적힌 곳들이 그 뒤 ADR-19 로 대부분 편입됐고,
2절 robots 표(8곳)는 ADR-21 재설계로 대체됐다.

# 25. 회차 리포트 대장

긴 호흡 실행이 끝날 때마다 `guide-reporter` 가 여기에 **한 행**을 남긴다.

리포트 본문의 정본은 아티팩트다. 저장소에는 이 대장 한 행과 `CLAUDE.md` 변경 이력 한 행만 남는다.
본문 HTML 을 저장소에 두지 않는 이유는 두 가지다. 첫째, 이 저장소의 푸시는 곧 공개 배포라
리포트가 그대로 웹에 올라간다. 둘째, 리포트는 그때의 판단이 담긴 문서라 나중에 고쳐 쓰면
당시의 근거가 사라진다.

**이 대장이 없으면 아티팩트 주소가 사라진다.** 세션이 끝나면 스크래치패드도 없어지므로,
다음 회차에 같은 리포트를 고쳐 내려면 여기 적힌 주소를 `url` 로 주는 길밖에 없다.

## 적는 법

| 칸 | 내용 |
|---|---|
| 날짜 | 리포트를 발간한 날 (YYYY-MM-DD) |
| 대상 기간 | 회차의 시작 커밋 ~ 끝 커밋 (짧은 해시) |
| 아티팩트 | 발간된 주소. 발간에 실패했으면 `미발간 — 사유` |
| 요지 | 한 줄. 무엇을 했고 무엇을 물었는지 |
| 결정 요청 | 개수와 제목. 답을 받으면 그 행에 `→ 답: …` 을 덧붙인다 |

결정 요청 칸을 채워 두는 이유는, 주소가 열리지 않는 상황에서도 **무엇을 물었는지는 남게**
하기 위해서다. 다음 회차의 리포터는 이 칸을 먼저 읽고 답을 받지 못한 것을 다시 올린다.

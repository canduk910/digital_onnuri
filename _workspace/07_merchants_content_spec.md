### M4. 결과 표
- 헤더: `가맹점명` · `분류` · `소속 시장·상점가` · `지역` · `취급품목`
- `지역` 셀은 시도명(서울/인천/경기). `소속 시장·상점가` 셀이 이 페이지의 위치 정보 전부이므로 헤더에 "주소"라는 단어를 쓰지 않는다 — "주소" 헤더를 쓰는 순간 이용자는 번지수를 기대한다.
- 디지털형/지류형 — **확정**: 토글 `디지털형만 보기` 제공, **기본 ON**(디지털형 가맹점만 표시). 해제 시 지류형 전용 가맹점까지 표시하며 해당 행에 배지 `지류만`. 이 페이지는 디지털온누리 가이드의 부속이므로 기본값이 디지털형인 이유를 토글 근처에 쓸 필요는 없다 — M6 각주 ①이 담당.
- 등록년도 컬럼은 싣지 않는다(행동에 도움이 안 되는 정보 — 표를 좁게 유지). data JSON에 있어도 렌더 생략.

### M5. 빈 결과 안내
- 기존 페이지 패턴(`"{q}"에 해당하는 항목이 없습니다.` + `검색 초기화`)을 확장:

> `"{q}"에 해당하는 가맹점이 없습니다.`
> `이 목록은 시장·상점가 소속 가맹점({snapshot_date} 기준)만 담고 있어, 여기 없어도 실제로는 가맹점일 수 있습니다 — 온누리 앱 '가맹점 찾기' 지도에서 점포 단위로 확인하세요.`
> 버튼: `검색 초기화` · 링크: `앱 가맹점 지도로 확인 ↗` (onnuri.gift/place)

- 필터만 걸고 결과가 0일 때(검색어 없음)도 두 번째 문장과 링크는 동일하게 노출.
- 단정 강도: 확인지시 (스냅샷 누락 가능성 — low)

### M6. 각주
- ① 출처: `※ 출처 — 공공데이터포털 '온누리상품권 가맹점 현황' {snapshot_date} 기준 스냅샷, 수도권(서울·인천·경기) 수록. 기본 표시는 디지털형 가맹점이며, '디지털형만 보기'를 끄면 지류형 전용 가맹점('지류만' 표시)까지 보입니다. 연 1회 갱신 자료로 다음 갱신은 {next_update} 예정입니다.`
- ② 위치: `※ 이 자료에는 점포 주소가 없습니다 — 위치는 소속 시장·상점가 단위이며, 같은 시장 안에서도 점포 위치·영업 여부는 다를 수 있습니다.`
- ③ 최종 확인(기존 가이드 각주 ⑤와 같은 결어로 통일): `※ 가맹 여부는 수시로 바뀌므로 결제 전 온누리 앱 '가맹점 찾기'에서 최종 확인이 필요합니다.`
- 확인 수단의 위계를 어디서나 동일하게: **이 목록 = 참고용 스냅샷, 앱 지도 = 최종 확인.** 기존 가이드의 각주 체계와 상충하지 않게 유지한다.

데이터 성격이 기존 뷰와 다르다: 온누리 가맹점찾기 조회 결과의 실시간 수집본(수집일은 meta에서 — 현행 2026-08-07)이라 **기존 공공데이터 스냅샷(2025-07-31)과 기준일이 다르고**, **도로명 주소가 있으며**, **가맹 등록 점포만 수록**된다(직영 SSM은 애초에 없음). 문구 전체가 이 세 차이를 이용자에게 정확히 전달해야 한다.

#### M8-1. 뷰 전환 UI 라벨
- 기존 뷰: `시장·상점가` / 신규 뷰: `브랜드 매장`
  - 지시안 "시장 가맹점 vs 브랜드·생활매장"에서 조정: 두 뷰의 실제 축은 **위치(어느 시장) vs 브랜드(어느 체인)**이므로 라벨도 그 축으로 대비시킨다. "생활매장"은 풀이 없이는 와닿지 않는 말이라 제외 — 다이소·편의점이 모두 "브랜드 매장"으로 자연스럽게 묶인다.
- 각 탭 보조 설명(탭 아래 1줄):
  - 시장·상점가: `전통시장·상점가 소속 가맹점 — 위치는 시장 이름 단위`
  - 브랜드 매장: `편의점·마트·기업형 슈퍼·다이소 가맹 점포 — 도로명 주소 제공`
- 단정 강도: 사실 표기

#### M8-2. 고지 문구 (브랜드 뷰 전용 배너 — M2 배너는 시장·상점가 뷰에서만 표시)

>
> 여기 실린 점포는 모두 가맹 등록된 곳이고 도로명 주소까지 확인됩니다 — 다만 수집일 이후 해지됐을 수 있으니, 결제 전 온누리 앱 '가맹점 찾기' 확인은 똑같이 필요합니다.

- 단정 강도: 수집본 성격·주소 제공은 사실 표기, 개별 점포 현재 상태는 확인지시

- ② SSM: `※ 이 목록의 GS더프레시 등 기업형 슈퍼(SSM) 브랜드 점포는 모두 가맹 등록된 개인 가맹점주 점포입니다 — 직영점은 가맹 대상이 아니라 이 목록에 없고, 결제도 되지 않습니다.`

- ③ 최종 확인: M6 ③과 동일 문구 재사용 — `※ 가맹 여부는 수시로 바뀌므로 결제 전 온누리 앱 '가맹점 찾기'에서 최종 확인이 필요합니다.`

## data / dev 전달 사항

1. **[data 확정 대기 — 카테고리 매핑]** 칩 표시명·순서는 M3 표대로 확정. 취급품목→카테고리 매핑 규칙 확정 시 키 이름만 맞춰 달라. 매핑 결과에 체육시설·교습소류가 학원에 포함되면 표시명을 `학원·체육시설`로 알려달라(기존 판정표와 통일 목적).
2. **[확정 반영]** 디지털형 토글 — `디지털형만 보기` 기본 ON, 해제 시 지류 전용 포함 + `지류만` 배지 (M4·M6 ①에 반영 완료).
3. **[data 요청 — meta 필드]** merchants JSON meta에 `snapshot_date`("2025-07-31"), `next_update`("2026-08-12"), `source`(공공데이터포털 자료명), `scope`(서울·인천·경기) 포함 필요 — D1이 전부 여기서 나온다. 시도별 건수 필드는 **불요**(D2 — 미로드 시도 칩은 `선택 시 불러오기` 표시로 확정, 파생값 필드 최소화).
4. **[dev]** M2 배너는 검색 UI보다 위, 스크롤 없이 보이는 위치. 날짜·건수는 D1~D5 계산식 외 하드코딩 금지. M7 링크는 index.html S4 지도 검색 박스 아래 삽입.
5. **[문체]** 약국 칩·행이 노출되므로, 기존 확정 문구("약국은 가맹 유지, 처방약 결제 범위는 결제 전 약국·앱에서 확인")와 상충하는 서술을 이 페이지에 추가하지 않는다 — 약국 관련 보충 설명이 필요하면 가이드 본문으로 링크만.
6. **[data 요청 — 브랜드 매장 JSON meta]** 수집일 필드(D6 — 현행 "2026-08-07"), `source`(온누리 가맹점찾기 + 수집 경로가 비공식 API임을 데이터 리포트/meta note에 기록), 구/시 필드(D8) 필요. 필드 이름은 기존 merchants 파일 관례(`dataset_version`·`generated_on` 등)에 맞춰 data가 결정하되, **시장 뷰 기준일 필드와 별개**여야 한다(D6 사유).
7. **[dev — M8]** M2 배너와 M8-2 배너는 활성 뷰에 따라 하나만 표시. M1 보조행 기준일은 활성 뷰 기준 전환(D10). 브랜드 뷰 표에는 도로명 주소 컬럼 추가 — 시장·상점가 뷰 표의 "주소 단어 금지" 규칙(M4)은 브랜드 뷰에는 적용되지 않는다(실제 주소가 있으므로).

### M10-1. 지역 계층 필터 — 구조와 문구 (핵심)
시도(서울/인천/경기) 선택 후 그 아래를 계단식으로 좁힌다. 시도별 계층 깊이가 다르다:

| 시도 | 계층 | 이유 |
|------|------|------|
| 서울 | **구 → 동** (2단계) | 특별시 = 25개 자치구 아래 행정동. 필드: `gu` → `dong`(`si`=null) |
| 인천 | **구 → 동** (2단계) | 광역시 = 11개 구/군 아래 행정동. 필드: `gu` → `dong`(`si`=null) |
| 경기 | **시 → 구 → 동** (최대 3단계) | 도 아래 31개 시. 필드: `si`(시) → `gu`(구) → `dong`. 단 **`gu`는 일반구 20개(수원 4·성남 3·안양 2·안산 2·고양 3·용인 3·부천 3)뿐** — 나머지 24개 시는 `gu` 없음 |

- **경기 '구 없는 시' 처리**: 선택된 `si`의 아이템에 `gu` 값이 하나도 없으면 → **구 단계를 자동 생략**하고 `시 → 동` 2단계로 접는다. 빈 구 드롭다운을 절대 노출하지 않는다. (경기 일반구는 data가 화이트리스트 20종으로 정리 — 유령 구 0.)
- **필드 매핑**(dev 분기): 서울·인천 = `[gu, dong]`(최상위가 시도 자체). 경기 = `[si, gu?, dong]`. 동은 세 시도 모두 `dong`.
- **`dong` null(약 7.1%) 폴백**: 도로명주소에 법정동 괄호가 없어 동이 비는 점포가 있다. 처리:
  - 동 드롭다운에 **`동 미상`** 옵션을 별도로 둔다(동이 null인 점포 모음). `동 전체`(전 범위)와 **구분** — `동 전체`는 필터 없음, `동 미상`은 "동을 못 뽑은 점포만".
  - 결과 표의 동 칸은 null이면 `동 미상`으로 표기(빈칸 방치 금지). 구까지는 전건 확정이므로 위치 파악은 구·도로명 주소로 가능.
- **UI**: 계단식 드롭다운(권장) 또는 계층 칩. 상위 미선택이면 하위는 비활성. 기본 옵션:
  - 1단계 기본값: `구 전체`(서울·인천) / `시 전체`(경기)
  - 경기 2단계(구) 기본값: `구 전체`
  - 동 기본값: `동 전체` (+ 목록 끝에 `동 미상`)
- **미선택 = 상위 범위 전체**. 예: 서울 + `구 전체` = 서울 전체, 서울 + 강남구 + `동 전체` = 강남구 전체.
- **옵션 목록은 데이터에서 생성**(가나다순) — 구·시·동 이름을 템플릿에 나열하지 않는다(D11·D13·D14). 상위 선택이 바뀌면 하위 옵션을 그 상위 아이템에서 다시 유도.
- **결과 표에 주소·동 노출**: `addr`(도로명)·`gu`/`dong`이 있으므로 표에 도로명 주소(또는 `구/동`) 컬럼을 둔다(M4의 "주소 단어 금지"는 통합 뷰에 비적용 — 실제 주소가 있으므로).

- `{collected_on}`은 API meta 수집일(현행 2026-08-08) — D12. "스냅샷"·"공공데이터"·연 1회 갱신 표현은 쓰지 않는다(이제 API 수집분).

### M10-2b. 한계 고지 갱신 (task #19 지시 — data 확정 반영)
데이터 성격이 바뀌었으니 한계 고지도 교체한다:
- **삭제**: 기존 M2 각주 ②의 "**점포 주소가 없습니다 / 위치는 소속 시장 단위**" 고지 — 이제 도로명 주소가 있으므로 **삭제**.
- **삭제**: "일부 점포 누락 가능"류 문장 — data가 **구·군 addrCd 전수 순회**로 수집(키워드 아님)했으므로 불요. (66,211곳 전수 규모.)
- **신규**(각주 또는 배너 하단 소자):
  `※ 이 자료는 온누리 가맹점찾기(비공식 조회)에서 수집했습니다. 구·시까지는 확정값이지만 동(洞)은 도로명 주소에서 뽑은 값이라 약 7%는 '동 미상'이며 일부 부정확할 수 있습니다. 정확한 위치·현재 가맹 여부는 결제 전 온누리 가맹점 지도나 디지털온누리 앱에서 확인하세요.`
  - 이유(정확도 눈금): 구·시는 쿼리 addrCd로 확정(파싱 아님)이라 단정, **동만 주소 파싱**이라 결측·오분류 가능 — 계층 필터의 동 단계가 어긋나 보일 때를 대비한 정직한 고지. "행정구역 전체가 부정확"으로 과장하지 않는다(구/시는 정확).

### M10-3. 필터 3축 — 업종(cat) · 브랜드(brand) · 시장 유형(market_type) — **확정**
세 축이 각각 다른 필드다. 배치: **업종 칩줄이 주(主) 필터로 상시 노출**, 브랜드·시장 유형은 **보조 필터**(소수·특수 목적이라 접힘/드롭다운 또는 한 줄 아래). 이유: `cat`는 전 점포를 덮어 누구나 쓰고, `brand`(ssm·daiso는 극소수)·`market_type`은 특정 이용자의 좁히기용이라 상시 노출하면 주 칩줄을 흐린다.

**① 업종 칩 (주 — `cat` 10종)** — 표시명·순서(빈도·이용 동선 순):

| 순서 | `cat` 값 | 화면 표시명 | 비고 |
|------|--------------|-------------|------|
| 1 | (전체) | `전체` | 기본 선택 |
| 2 | 음식점 | `음식점·카페` | 최다 이용 |
| 3 | 편의점 | `편의점` | |
| 4 | 마트·슈퍼 | `마트·슈퍼` | (SSM은 brand 축에서 별도 분리) |
| 5 | 농축수산·식품 | `농축수산·식품` | 장보기 |
| 6 | 의류·신발 | `의류·신발` | |
| 7 | 생활·잡화 | `생활·잡화` | (다이소는 brand 축에서 별도 분리) |
| 8 | 생활서비스 | `생활서비스` | |
| 9 | 약국 | `약국` | 03 확정 문구 승계(가맹 유지·처방약 범위 앱 확인) |
| 10 | 학원 | `학원·교습소` | 03 판정표와 통일 |
| 11 | 기타 | `기타` | 항상 마지막 |

- 각 칩 카운트 `{label} {count}` = 현재 지역 계층 필터 적용 후 `cat` 집계(D7). 칩 라벨은 03 판정표·M8-4와 통일.

**② 브랜드 필터 (보조 — `brand` 태그)** — 옛 '브랜드 매장 뷰' 보존용. `brand` 값(convenience / mart / ssm / daiso)을 칩으로:

| `brand` 값 | 화면 표시명 |
|-----------|-------------|
| convenience | `편의점` |
| mart | `마트·슈퍼` |
| ssm | `기업형 슈퍼(SSM)` |
| daiso | `다이소` |

- `brand=null`(대다수)은 브랜드 칩 미해당 — 브랜드 필터 미선택 시 전체 노출. 카운트는 `brand`별 집계(D17), **숫자 하드코딩 금지**(ssm·daiso는 극소수라 특히 계산식으로).
- 업종 칩(`편의점`/`마트·슈퍼`)과 브랜드 칩(`편의점`/`마트·슈퍼`)이 라벨이 겹칠 수 있으니, 브랜드 필터 영역에 "브랜드" 구획 제목을 달아 축을 구분(색만으로 구분 금지 — S15 접근성 원칙 승계).

**③ 시장 유형 필터 (보조 — `market_type`)** — 옛 '시장·상점가 뷰' 보존용. 전통시장 등 소속 유형으로 좁히기. 옵션은 `market_type` 유니크 값에서 생성(전통시장/골목형상점가/상점가/지하도상점가/활성화구역/백년소상공인 — 하드코딩 금지, D15). 미소속 점포도 있으므로 `전체` 기본.

- **SSM 각주 연결**: `brand=ssm` 칩·행에 M10-6 SSM 각주를 연결(직영 제외/개인 가맹점).

### M10-5. 지역 혼동 주의 (승계)
- 공식 지도는 전국 서비스 — 어떤 문구·라벨에서도 "특정 지역만 가능"으로 서술 금지(policy U5). 이 페이지의 수도권(서울·인천·경기)은 **우리 수집 범위**일 뿐 제도·지도의 지역 제한이 아니다.
- 계층 필터에 없는 구/동은 "해당 지역에 가맹점이 없다"가 아니라 **"우리 수집분에 없다"**일 수 있음 — 빈 결과 문구가 이를 흡수(M10-4).

### M10-6. 기존 확정 사항 승계 (변경 없음, 필드만 조정)
- **SSM 각주**: M8-5 ②를 그대로 승계 — `※ 이 목록의 GS더프레시 등 기업형 슈퍼(SSM) 브랜드 점포는 모두 가맹 등록된 개인 가맹점주 점포입니다 — 직영점은 가맹 대상이 아니라 이 목록에 없고, 결제도 되지 않습니다.` (**`brand=ssm`** 칩·행에 연결 — data 최종 brand 태그 기준. 03 S4·S6·S14 직영/가맹 축과 일관.)
- **약국**: `cat=약국` 관련 보충은 03 확정 문구("약국은 가맹 유지, 처방약 결제 범위는 결제 전 약국·앱에서 확인")와 상충하는 서술 추가 금지.
- **최종 확인 링크**: M6 '확인 경로 링크 규격' 그대로 — 1차 `온누리 공식 가맹점 지도로 확인 ↗`(웹), 2차 `디지털온누리 앱 설치`(App Store·Google Play). M10-2 배너·M10-4 빈 결과에서 이 규격 참조.
- **index.html 진입**: 03 S15 서브탭 1('가맹점 찾기')이 이 페이지 진입 정본(변경 없음).
- **디지털/지류 필터(M4 개정)**: data에서 **`paper`는 전건 Y**(지류 필터 무의미), 디지털 여부는 `card`/`qr`로 갈린다(card Y 64,997/66,211). 따라서:
  - 기존 M4의 "디지털형만 보기 기본 ON + `지류만` 배지" 구조는 **폐기**(모두 지류 가맹이라 '지류만' 구분이 성립 안 함).
  - 대신 **선택 필터** `디지털(카드·QR) 결제 가능만` 제공(기본 OFF, 전체 표시). 판정 = `card==='Y' || qr==='Y'`. 이 페이지가 디지털온누리 가이드의 부속이므로, 카드·QR 결제가 안 되는 소수 점포를 걸러 보고 싶은 이용자를 위한 옵션.
  - 표의 결제수단 표기: `카드`/`QR` 가능 여부를 배지로(있는 것만). `지류` 배지는 전건이라 표기 생략. (숫자는 계산식 — 하드코딩 금지.)

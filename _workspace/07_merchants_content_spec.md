- 작성: guide-content-writer (2026-08-06)
- 대상: 별도 페이지 `merchants.html` — 수도권(서울·인천·경기) 가맹점 검색
- 입력: `_workspace/raw/onnuri_merchants.csv`(공공데이터포털 스냅샷), team-lead 과업 지시(task #8), 기존 가이드 문체(`03_content_spec.md`)
- 데이터 성격(문구 전체를 지배하는 두 가지 한계):
  1. **주소 없음** — 위치 정보는 "소속 시장·상점가명 + 시도"까지만. 개별 점포 주소·좌표 없음.
  2. **연 1회 스냅샷** — {snapshot_date} 기준. 이후 가맹·해지 변동 미반영. 차기 갱신 {next_update} 예정.

- 단정 강도: 스냅샷 수록 사실은 사실 표기, **개별 점포의 현재 가맹 여부는 구조적으로 low** — 반드시 확인 지시 어조. "이 목록에 있으니 결제된다"로 읽히는 문장 금지.

플레이스홀더: `{snapshot_date}` = merchants meta.snapshot_date(현행 "2025-07-31"), `{next_update}` = meta.next_update(현행 "2026-08-12"). 둘 다 data JSON meta에서 읽는다 — 템플릿에 날짜를 심지 않는다.

## 문구

### M1. 헤더
- 제목: `디지털온누리상품권 가맹점 검색`
- 부제: `수도권 가맹점 찾기 — 서울·인천·경기, 시장·상점가 단위`
- 보조행(기존 index.html 헤더 부제와 같은 자리): `공공데이터포털 가맹점 현황 {snapshot_date} 기준 · {region_name} {region_total}곳 · ` + 가이드로 돌아가는 링크 `← 사용처 가이드`
  - `{region_name}` = 현재 선택된 시도명(서울/인천/경기), `{region_total}` = 해당 시도 수록 건수 (D5). **수도권 그랜드 총계는 쓰지 않는다** — 시도별 지연 로드 아키텍처상 전체 탭이 없고, 총계 표시는 3개 파일 전량 로드를 강제해 지연 로드와 상충한다.
- 단정 강도: 사실 표기

### M2. 기준일·한계 고지 배너 — **이 페이지의 핵심. 접거나 각주로 내리지 말 것**
검색창 위, 눈에 띄는 배너 1개. 문장 3개:

> **이 목록은 {snapshot_date} 기준 공공데이터 스냅샷입니다.** 연 1회 갱신되는 자료라(다음 갱신 {next_update} 예정) 그 이후의 신규 가맹·해지는 반영돼 있지 않습니다.
>
> **개별 점포의 주소는 제공되지 않습니다.** 위치는 소속 시장·상점가 이름까지만 확인됩니다 — 여기서 가게를 찾았어도, 방문 전에 온누리 앱 '가맹점 찾기' 지도에서 점포 위치와 현재 가맹 여부를 확인하세요.
>
> 여기 '가맹'으로 나와도 {snapshot_date} 이후 해지됐을 수 있고, 여기 없어도 새로 가맹했을 수 있습니다.

- 이유(장면): 스냅샷임을 모르면 "목록에 있으니 되는 가게"로 읽고 찾아갔다가 해지된 점포 앞에서 결제 실패. 세 번째 문장이 양방향 오독(있음=됨 / 없음=안 됨)을 모두 차단한다.
- 근거: task #8 지시(스냅샷 성격·차기 갱신일) / 단정 강도: 자료 성격은 단정(사실), 개별 점포 상태는 확인지시(low)

### M3. 검색·필터 라벨
- 검색창 placeholder: `가게 이름·시장 이름·취급품목 검색 (예: 떡집, ○○시장)`
- 시도 칩: `서울 {seoul}` · `인천 {incheon}` · `경기 {gyeonggi}` — **전체 칩 없음**(시도별 지연 로드 — 하나의 시도가 항상 선택된 상태). 기본 선택 시도는 dev 결정. 칩 카운트는 동적(D2) — 미로드 시도의 카운트는 meta의 시도별 건수 필드로 표시(전달 사항 3)
- 카테고리 칩 — **화면 표시명·순서 (라벨은 확정, 매핑 규칙은 data 확정 대기)**:

| 순서 | data 카테고리 키(설계 중) | 화면 표시명 | 순서 근거 |
|------|--------------------------|-------------|-----------|
| 1 | (전체) | `전체` | 기본 선택 |
| 2 | 음식점 | `음식점·카페` | 이용 빈도 최상 — 기존 판정표 라벨과 통일 |
| 3 | 마트·슈퍼 | `마트·슈퍼` | 장보기 동선 |
| 4 | 편의점 | `편의점` | |
| 5 | 약국 | `약국` | |
| 6 | 학원 | `학원·교습소` | 기존 판정표는 "학원·체육시설" — 매핑에 체육시설 포함 시 `학원·체육시설`로 통일할 것(아래 전달 사항 2) |
| 7 | 기타 | `기타` | 항상 마지막 |

  - 각 칩에 카운트 표기: `{label} {count}` (기존 index.html 칩 패턴과 동일, D3)
  - **[data 확정 대기]** 취급품목→카테고리 매핑 규칙이 미확정. 매핑 확정 후 라벨과 실데이터 분포가 어긋나면(예: 체육시설 포함 여부) 표시명만 이 표 기준으로 조정한다.
- 정렬 안내(기존 패턴 유지): `기본 순서 — 이름순 (가나다)`
- 검색 결과 카운트: `{countText}` — D4

### M4. 결과 표
- 헤더: `가맹점명` · `분류` · `소속 시장·상점가` · `지역` · `취급품목`
- `지역` 셀은 시도명(서울/인천/경기). `소속 시장·상점가` 셀이 이 페이지의 위치 정보 전부이므로 헤더에 "주소"라는 단어를 쓰지 않는다 — "주소" 헤더를 쓰는 순간 이용자는 번지수를 기대한다.
- 디지털형/지류형 — **확정**: 토글 `디지털형만 보기` 제공, **기본 ON**(디지털형 가맹점만 표시). 해제 시 지류형 전용 가맹점까지 표시하며 해당 행에 배지 `지류만`. 이 페이지는 디지털온누리 가이드의 부속이므로 기본값이 디지털형인 이유를 토글 근처에 쓸 필요는 없다 — M6 각주 ①이 담당.
- 등록년도 컬럼은 싣지 않는다(행동에 도움이 안 되는 정보 — 표를 좁게 유지). data JSON에 있어도 렌더 생략.

### M5. 빈 결과 안내
- 기존 페이지 패턴(`"{q}"에 해당하는 항목이 없습니다.` + `검색 초기화`)을 확장:

> `"{q}"에 해당하는 가맹점이 없습니다.`
> `이 목록은 시장·상점가 소속 가맹점({snapshot_date} 기준)만 담고 있어, 여기 없어도 실제로는 가맹점일 수 있습니다 — 온누리 앱 '가맹점 찾기' 지도에서 점포 단위로 확인하세요.`
> 버튼: `검색 초기화` · 링크: `앱 가맹점 지도로 확인 ↗` (onnuri.gift/place)

- 필터만 걸고 결과가 0일 때(검색어 없음)도 두 번째 문장과 링크는 동일하게 노출.
- 단정 강도: 확인지시 (스냅샷 누락 가능성 — low)

### M6. 각주
- ① 출처: `※ 출처 — 공공데이터포털 '온누리상품권 가맹점 현황' {snapshot_date} 기준 스냅샷, 수도권(서울·인천·경기) 수록. 기본 표시는 디지털형 가맹점이며, '디지털형만 보기'를 끄면 지류형 전용 가맹점('지류만' 표시)까지 보입니다. 연 1회 갱신 자료로 다음 갱신은 {next_update} 예정입니다.`
- ② 위치: `※ 이 자료에는 점포 주소가 없습니다 — 위치는 소속 시장·상점가 단위이며, 같은 시장 안에서도 점포 위치·영업 여부는 다를 수 있습니다.`
- ③ 최종 확인(기존 가이드 각주 ⑤와 같은 결어로 통일): `※ 가맹 여부는 수시로 바뀌므로 결제 전 온누리 앱 '가맹점 찾기'에서 최종 확인이 필요합니다.`
- 확인 수단의 위계를 어디서나 동일하게: **이 목록 = 참고용 스냅샷, 앱 지도 = 최종 확인.** 기존 가이드의 각주 체계와 상충하지 않게 유지한다.

### M7. index.html → merchants.html 진입 링크 (1개)
- 위치: 오프라인 탭 S4 요건 2의 '지도 검색' 안내 박스 바로 아래(같은 박스 스타일).
- 문구: `수도권 가맹점 검색 ↗ — 서울·인천·경기 가맹점을 상호·소속 시장 이름으로 찾아볼 수 있습니다 (공공데이터 스냅샷 기준, 최종 확인은 앱 지도)`
- 날짜는 링크 문구에 넣지 않는다 — index.html이 merchants meta까지 읽는 교차 의존을 만들지 않기 위함. 기준일 고지는 merchants.html 도착 즉시 M2 배너가 담당한다. "스냅샷 기준·최종 확인은 앱"만 링크에 남겨 과신 진입을 막는다.

## data / dev 전달 사항

1. **[data 확정 대기 — 카테고리 매핑]** 칩 표시명·순서는 M3 표대로 확정. 취급품목→카테고리 매핑 규칙 확정 시 키 이름만 맞춰 달라. 매핑 결과에 체육시설·교습소류가 학원에 포함되면 표시명을 `학원·체육시설`로 알려달라(기존 판정표와 통일 목적).
2. **[확정 반영]** 디지털형 토글 — `디지털형만 보기` 기본 ON, 해제 시 지류 전용 포함 + `지류만` 배지 (M4·M6 ①에 반영 완료).
3. **[data 요청 — meta 필드]** merchants JSON meta에 `snapshot_date`("2025-07-31"), `next_update`("2026-08-12"), `source`(공공데이터포털 자료명), `scope`(서울·인천·경기), **시도별 건수**(D2 — 미로드 시도 칩 표시용) 포함 필요 — D1·D2가 전부 여기서 나온다.
4. **[dev]** M2 배너는 검색 UI보다 위, 스크롤 없이 보이는 위치. 날짜·건수는 D1~D5 계산식 외 하드코딩 금지. M7 링크는 index.html S4 지도 검색 박스 아래 삽입.
5. **[문체]** 약국 칩·행이 노출되므로, 기존 확정 문구("약국은 가맹 유지, 처방약 결제 범위는 결제 전 약국·앱에서 확인")와 상충하는 서술을 이 페이지에 추가하지 않는다 — 약국 관련 보충 설명이 필요하면 가이드 본문으로 링크만.

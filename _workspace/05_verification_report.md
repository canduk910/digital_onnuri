#### D-F1. 번들 언패킹 실패로 페이지 전면 미렌더 (치명)
- 심각도: **치명**
- 경계면: 렌더
- 왼쪽(관측): 원본 `index.html.bak-20260806` L388 template 문자열 — 임베드 닫는 태그가 유니코드 이스케이프됨:
  `...<script src=\"0c19069d-...\"></script>\n\n</head>...` (첫 리터럴 `</script>`까지 캡처 길이 85,115자, 리터럴 `</script>` 0개)
- 오른쪽(관측): 현재 `index.html` L388 template 문자열 — 같은 자리가 **리터럴** `</script>`:
  `...<script src=\"0c19069d-...\"></script>` (`<script type="__bundler/template">` 요소가 char 186에서 조기 종료, 리터럴 `</script>` 2개)
- 화면(관측): 로더 토스트 `Error unpacking: Unterminated string in JSON at position 186 (line 2 column 186)`. `get_page_text` 결과에 `{{ baseMonth }}`·`{{ onTabText }}`·`{{ row.t }}`·`{{ regionApps }}` 등 머스태시가 리터럴로 남고 `<sc-for>` 반복이 전개되지 않음(데이터 행 0개).
- 원인(재현): dev의 `build_index.py`가 template을 `json.dumps`로 재인코딩하면서, 원본이 HTML 안전을 위해 `/`로 이스케이프해 두었던 임베드 닫는 태그(`</script>`, `</head>` 등)가 **리터럴 `/`로 복원**됨. `json.dumps`는 `/`를 이스케이프하지 않는다. 브라우저 HTML 파서는 `<script type="__bundler/template">` 요소 안에서 첫 리터럴 `</script`를 만나면 그 지점에서 스크립트를 닫아 버리므로, 로더 L75 `JSON.parse(templateEl.textContent)`가 잘린(미완결) 문자열을 파싱하다 position 186에서 실패한다. `manifest`·`page_order`·`ext_resources` 파싱은 정상(해당 블록에 리터럴 `</script>` 없음) — **template만** 깨진다.

- 담당: **guide-frontend-dev**
- 수정 제안: `build_index.py`에서 template JSON을 스크립트 요소에 심기 전, 임베드 닫는 태그의 `/`를 원본과 동일하게 이스케이프한다. 최소 요건은 `</script`가 리터럴로 남지 않는 것 — 예: `json.dumps` 산출물에 `.replace('</', '<\\/')`(JSON에서 `<\/`는 유효하며 HTML 파서는 `</script`로 인식하지 않음), 또는 원본과 같이 `/`→`/`. 수정 후 반드시 **브라우저로 실제 마운트**를 재확인(정적 `json.loads`·`node --check`는 이 HTML 파서 레벨 조기 종료를 못 잡는다 — 이번에 통과했음에도 렌더가 깨진 이유).

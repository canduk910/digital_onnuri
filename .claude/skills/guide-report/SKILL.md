# 리포트 — 한 회차를 결정권자의 언어로 옮기는 절차

리포트의 실패는 틀린 문장이 아니라 **읽히지 않는 문장**이다. `CLAUDE.md` 변경 이력은 한 칸에 배경·원인·조치·검증을 눌러 담은 로그이고 그 압축은 의도된 것인데, 그 칸을 그대로 복사해 리포트 문단으로 쓰는 것이 여기서 가장 나오기 쉬운 실패다. 독자는 계산대 앞 이용자가 아니라 **결정권자**이고, 그가 묻는 것은 셋뿐이다 — 지금 무엇이 잘못돼 있나, 그대로 두면 누가 무엇을 겪나, 내가 지금 정할 것은 무엇인가.

## 기초정보는 기억이 아니라 명령으로 모은다

세션의 기억은 회차가 길어질수록 앞부분을 잃는다. 리포트를 쓰기 전에 네 갈래를 **다시 재서** 시작한다.

```bash
# 1. 이번 회차에 무엇을 했나 — 커밋 목록·본문·범위
git log --since='YYYY-MM-DD 00:00' --format='%ad|%s' --date=short
git log --since='YYYY-MM-DD 00:00' --format='===%n%s%n---%n%b'   # 본문에 원인·실측·검증이 있다
git log --since='YYYY-MM-DD 00:00' --format='%ad' --date=short | sort | uniq -c
git show --stat <해시>                                            # 그 커밋이 실제로 만진 파일
```

```bash
# 2. 지금 초록인가 — 문서를 믿지 말고 직접 돌린다 (명령의 정본은 dev-testing 스킬)
#    ※ 출력에 FAIL 이 없다고 통과가 아니다. 반드시 종료 코드를 함께 본다.
for t in test_frontend_static.js test_survey_probe.js test_index_nightly.js; do
  node _workspace/dev_scripts/$t >/dev/null 2>&1; echo "$t EXIT=$?"
done
for t in test_robots_watch.py test_canary_trend.py verify_build.py; do
  python3 _workspace/dev_scripts/$t >/dev/null 2>&1; echo "$t EXIT=$?"
done
(cd backend && ./gradlew test)                            # JAVA_HOME 지정은 dev-testing 참조

# 브라우저가 필요한 것 — NODE_PATH 를 빼면 실패가 아니라 종료 코드 2로 '건너뜀'이 된다.
# NODE_PATH 값의 정본은 dev-testing 스킬의 「자동 테스트」 절이다. 그 값을 그대로 쓴다.
NODE_PATH=<dev-testing 참조> PLAYWRIGHT_CHANNEL=chrome \
  node _workspace/dev_scripts/test_frontend_render.js; echo "render EXIT=$?"
NODE_PATH=<dev-testing 참조> PLAYWRIGHT_CHANNEL=chrome \
  node _workspace/dev_scripts/test_merchants_smoke.js;  echo "smoke  EXIT=$?"
```

`EXIT=0` 만 통과다. `EXIT=2` 는 **실행되지 않았다**는 뜻이므로 5절에 `확인: 미확인` 으로 적고,
3절에 "그 층의 회귀는 이번 회차에 확인되지 않았다"를 남긴다. 통과 건수만 옮겨 적으면
건너뛴 회차와 통과한 회차가 리포트에서 구분되지 않는다.

```bash
# 3. 남은 과제 — 정본은 하나다. 줄 번호로 자르지 않는다(문서가 늘면 조용히 덜 읽는다)
grep -n '^## \|^### ' _workspace/23_backlog.md   # 먼저 목차를 보고 필요한 절을 통째로 읽는다

# 4. 데이터 신선도 — 층마다 따로 잰다
python3 -c "import glob,json; [print(f, json.load(open(f))['meta']['collected_on']) for f in glob.glob('data/merchants/*.json')]"
python3 -c "
import json,collections
d=json.load(open('data/online_catalog.json'))
print(collections.Counter(i.get('surveyed_on') for i in d['items']))
print('meta.collected_on =', d['meta']['collected_on'])"
```

| 원천 | 리포트에서 답하는 것 | 빠뜨리면 |
|---|---|---|
| `git log` 본문 | 무엇이 왜 달라졌나, 어느 해시를 되돌리면 되나 | 회차가 "많이 했다"로만 남는다 |
| 테스트 직접 실행 | 지금 초록인가, 무엇이 게이트 밖인가 | 어제의 초록을 오늘 것으로 옮겨 적게 된다 |
| `23_backlog.md` | 이번에 닫힌 것과 새로 열린 것 | 같은 과제를 두 회차 연속 새로 발견한다 |
| `data/*.json` 날짜 | 화면이 지금 몇 일 낡은 말을 하나 | 조용히 낡은 데이터가 리포트에서도 안 보인다 |

**커밋 수를 성과로 세지 않는다.** 최근으로 올수록 커밋이 잘게 쪼개져(2026-09-02 12건, 09-05 59건) 커밋 수는 작업량이 아니라 쪼개기 습관을 잰다. 세는 단위는 과제 묶음(`A1`·`C3` 같은 접두)이다.

## 숫자는 그 자리에서 재고, 문서에서 베끼지 않는다

이 저장소의 문서에 적힌 건수는 낡는다. 실제로 그랬다 — 2026-09-05 시점에 `dev-testing/SKILL.md` 는 프론트 정적 계약을 "66건"이라 적어 두었는데 그날 직접 돌리니 **163건**이었다. 리포트가 그 숫자를 인용하면 리포트도 함께 틀린다.

- 건수·곳 수·줄 수는 **리포트를 쓰는 그 회차에 실행하거나 세어서** 넣고, 옆에 기준일을 붙인다.
- 그 숫자가 어느 문서에도 필요하지 않다면 갱신이 아니라 **제거**가 맞다(`23_backlog.md` A7이 CI 스텝 이름의 건수를 두고 내린 결론).
- 리포트의 실측 표는 그때의 물증이므로 다음 회차에 덮어쓰지 않고 기준일과 함께 보존한다.

## 쉬운 문장으로 쓴다 — 기준은 완결된 문어체다

한 문장은 주어와 서술어를 갖추고 "-다"로 끝난다. 한 문장에 사실 하나를 담고, 다음 문장이 앞 문장을 받는다.

- 나쁨: "8/29~9/1 수집 실패(4일). fail-open 작동으로 데이터 보존. 단, 화면 문구 미갱신 → 인지 지연."
- 좋음: "2026-08-29부터 나흘 동안 가맹점 수집이 실패했다. 실패해도 배치를 세우지 않는 구조라 이전 데이터는 지켜졌다. 그런데 화면은 그동안 '매일 00:30 자동 최신화'라고 계속 말하고 있었고, 그래서 나흘 동안 아무도 몰랐다."

### 어려운 표현 → 쉬운 대체어

첫 등장에 한 문장으로 풀고, 그다음부터는 짧은 말을 그대로 써도 된다.

| 이 저장소의 말 | 리포트에 쓸 말 |
|---|---|
| 채록 | 몰 화면을 직접 열어 취급 품목을 옮겨 적는 일 |
| 편입 / 승격 | 조회 대상에 넣었다 / 대상으로 올렸다 |
| 조임 | 판정 기준을 더 엄격하게 한 것 |
| 카나리아 | 매일 정해진 질문을 던져 규칙이 깨졌는지 알아내는 자동 점검 |
| 가드 | 확인하고 막는 장치 |
| 폴백 | 서버가 응답하지 않을 때 대신 읽는 파일 |
| fail-open | 실패해도 배치를 세우지 않고 지나가되 실패 사실을 남기는 방식 |
| 델타 | 지난번과 달라진 부분 |
| 경계면 | 서버 응답과 화면이 맞닿는 지점 |
| 회귀 | 고쳤던 것이 다시 나빠지는 일 |
| 창구 | 입력이 어디로 들어오든 반드시 지나가는 함수 하나 |
| 정본 | 기준이 되는 원본 |
| 오탐 / 정탐 | 잘못 걸린 것 / 제대로 걸린 것 |
| 병기 / 기각 / 유예 | 함께 적는다 / 하지 않기로 했다 / 미뤄 둔다 |
| 스탬프 | 화면에 찍히는 "○○ 기준" 날짜 표시 |
| pageerror 0 | 브라우저 콘솔 오류 0건 |
| rate limit "분5일100" | 한 IP에서 1분에 5번, 하루에 100번까지 |

**바꾸지 않는 것**: 코드 식별자(`ProbeJudge`·`applyCat`·`search_url_template`), 파일 경로와 줄 번호(`merchants.html:1009` — 이것이 "직접 재봤다"의 증거다), API·환경변수(`POST /api/online/search`·`APP_ADMIN_KEY`), 상태값(`likely`·`none`·`unclear`·`partial` — 옆에 풀이만 붙인다), 커밋 해시·ADR 번호·단계 이름(`ea38f5b`·ADR-19·단계 A~F·D-F1), 몰 이름과 제도 용어(온누리핫딜·인어교주해적단·골목형상점가·선차감), 수치와 날짜 원형(79,800건·2026-09-05 — "약 8만"으로 뭉개지 않는다).

### 개조식·명사형 종결을 고친다

문장은 "-다"로 끝낸다. "~함·~됨·~필요했음"으로 끊지 않고, 표의 칸도 주어와 서술어를 갖춘다.

- 전(`CLAUDE.md:136`): "legacy 빌더 즉사(duration 0), stuck deployment 취소 필요했음"
- 후: "기존 빌더가 시작하자마자 실패했다(실행 시간 0초). 멈춰 있던 배포를 손으로 취소해야 했다."
- 전(`23_backlog.md:72`): "산출물이 남은 순간 `pull` 실패 → `set -e` 로 **배치 전체 사망**"
- 후: "배치가 만들어 둔 파일이 남아 있으면 `git pull` 이 실패한다. 스크립트가 `set -e` 로 시작하기 때문에 그 한 줄에서 배치 전체가 멈춘다."

### 기호를 줄인다

실측 빈도가 장르 차이를 보여 준다 — `CLAUDE.md` 는 가운뎃점 1,386개·화살표 319개·원문자 40개, `23_backlog.md` 는 가운뎃점 107개·화살표 7개다. 리포트는 뒤쪽을 따른다.

- 가운뎃점(·)은 같은 층위의 짧은 명사 **셋까지**. 넷 이상이면 목록으로 내리거나 문장으로 푼다.
- 화살표(→)는 **값이 변한 것에만** 쓴다("1,934 → 1,552줄"은 좋다). 인과의 화살표는 "…이면 …한다"로 바꾼다.
- 원문자(①②③) 나열은 문단이나 마크다운 번호 목록으로 편다.
- 줄표(—)는 살린다. 앞말을 되받아 강조하는 이 저장소의 장치다. 다만 한 문단에 두 번을 넘기지 않는다.

### 과장 어휘를 심각도를 낮추지 않고 바꾼다

"즉사·사망·죽는다·물고 있었다"는 심각도를 전하려는 의도는 맞지만 리포트 문어체가 아니다.

- "새 서버 구축이 즉사" → "새 서버를 세우려 하면 첫 명령에서 실패한다"
- "배치 전체 사망" → "배치가 그 자리에서 전부 멈춘다"
- "통과로 눙치지 않는다" → "통과한 것처럼 얼버무리지 않는다"

## 리포트 구조 — 절 순서와 각 절이 답하는 질문

| # | 절 | 답하는 질문 | 빠지면 |
|---|---|---|---|
| 1 | 한 화면 요약 | 지금 어떤 상태인가 (열 줄 이내) | 결정권자가 본문을 다 읽어야 상태를 안다 |
| 2 | 이번에 한 것 | 무엇이 달라졌나 — 과제 묶음 단위 + 커밋 해시 | 되돌릴 자리를 못 찾는다 |
| 3 | 지금 열려 있는 것 | 무엇이 아직 잘못돼 있고, 그대로 두면 누가 무엇을 겪나 | 위험이 다음 회차에 재발견된다 |
| 4 | 결정할 것 | 내가 지금 정할 것은 무엇인가 (아래 표 형식) | 리포트가 읽히고 아무 일도 안 일어난다 |
| 5 | 확인한 것 / 확인하지 못한 것 | 어디까지 믿어도 되나 | "확인했다"는 거짓 신호를 준다 |
| 6 | 다음 회차의 재개 지점 | 세션이 끊기면 어디부터 읽나 | 다음 사람이 처음부터 다시 훑는다 |

- 3절의 각 항목에는 **사람이 무엇을 겪는지** 한 문장을 반드시 붙인다. "채록이 26일 낡았다"가 아니라 "그 몰만 26일 낡은 날짜를 화면에 계속 달고 있다"가 결정권자가 읽어야 할 문장이다.
- 5절은 항목마다 근거의 세기를 밝힌다 — `확인: 직접 실행` / `확인: 문서만 봄` / `확인: 미확인`. 이 칸이 리포트에서 가장 먼저 무너진다.
- 맨 끝에 한 줄: "이 리포트는 AI가 작성했고, 직접 재서 확인한 항목과 문서를 읽고 판단한 항목이 섞여 있다."

## 결정 요청은 표로 고정한다

4절의 각 결정은 예외 없이 네 칸을 채운다. 칸이 비면 그것은 결정 요청이 아니라 하소연이다.

| 선택지 | 대가 | 권고 | 되돌리는 비용 |
|---|---|---|---|
| 그대로 둔다 | 그 몰 하나가 26일 낡은 채록 날짜를 계속 단다 | | 없음 (현 상태) |
| 주소를 넣고 다시 채록한다 | 자동화가 안 되어 사람이 한 번 붙어야 한다 | **권고** | `data/online_catalog.json` 한 파일을 되돌리면 된다 |
| 그 몰을 목록에서 뺀다 | 이용자가 쓸 수 있는 곳이 하나 사라진다 | | 되돌리기는 쉬우나 그동안의 이용자 손해는 못 되돌린다 |

- **"아무것도 하지 않는다"를 반드시 선택지에 넣는다.** 가장 자주 빠지고, 실제로 가장 자주 선택되는 안이다.
- 권고는 한 행에만 표시한다. 두 행에 붙으면 결정을 미룬 것이다.
- 되돌리는 비용은 배포 층마다 다르므로 층을 밝힌다. Pages와 NCP는 되돌리는 커밋을 푸시하면 몇 분 안에 원복되지만, **야간 배치는 "지금 반영" 경로가 없다**(`backend/DEPLOY.md:168`). 배치와 얽힌 결정은 결과가 다음 날 00:30에 처음 드러나고, 손으로 되돌리려면 서버에 붙어야 한다.

## 아티팩트로 발간한다

리포트는 터미널 스크롤백에 남기면 전달된 것이 아니다. 결정권자가 다른 기기에서 열 수 있어야 한다.

1. **`artifact-design` 스킬을 먼저 부른다.** 이 요청에 어느 정도의 디자인 품이 맞는지는 그 스킬이 정한다. 파일을 쓰기 전에 부른다 — 다 쓰고 나서 부르면 이미 정해진 모양을 정당화하게 된다.
2. 본문은 **세션 스크래치패드 디렉터리**에 `.html` 로 쓴다(경로는 시스템 프롬프트가 알려 준다). 저장소에 두지 않는다 — 문서 한 파일만 바꾼 커밋도 Pages 배포가 나가고(2026-09-05 실증), 리포트는 그렇게 나갈 물건이 아니다.
3. `Artifact` 도구에 그 파일 경로를 준다.
   - **새 리포트**: 경로만 주고 발간한 뒤, 돌아온 주소를 `25_report_log.md` 에 적는다.
   - **같은 세션에서 고칠 때**: 같은 파일을 고쳐 같은 경로로 다시 부르면 주소가 유지된다.
   - **세션이 바뀐 뒤 고칠 때**: 스크래치패드는 세션마다 다른 디렉터리라 **경로만으로는 새 주소가 생긴다.** `25_report_log.md` 의 주소를 `url` 로 주고, 먼저 `action: "read"` 로 읽어 그 내용 위에 고쳐 다시 발간한다. 이 단계를 건너뛰면 결정권자는 옛 주소를 계속 보고, 고친 내용은 아무도 안 보는 새 주소에 남는다.
4. 링크를 한 줄로 건넨다. 요약을 터미널에 다시 붙여 넣지 않는다.

## 산출물

리포트 본문의 정본은 아티팩트다. 저장소에는 두 줄만 남는다 — `_workspace/25_report_log.md` 에 회차 한 행(날짜 · 대상 기간 · 아티팩트 링크 · 한 줄 요지)과 `CLAUDE.md` 변경 이력 한 행(형식은 doc-commit 스킬). 링크는 어디에도 적히지 않으면 사라진다.

## 하면 안 되는 것

- **숫자를 지어내지 않는다.** 세지 않은 것은 "세지 않았다"고 적는다. 문서에 적힌 건수를 그대로 옮기는 것도 지어내는 것에 든다 — 위에서 본 66/163, 92/91이 그 사례다.
- **검증하지 못한 것을 통과로 쓰지 않는다.** 미검증과 통과는 다른 상태이고, 리포트에서 섞이는 순간 리포트 전체가 신뢰를 잃는다. 테스트를 못 돌렸으면 못 돌린 이유를 적는다.
- **이미 결정된 것을 다시 묻지 않는다.** 이 저장소에는 "영구 종료"로 못 박은 결정이 있다 — 카드 실적 단정 강도 · 정책자금 지급분이 걸리는 한도 · 하나카드 관찰(`21_night_audit_fixes.md:742-744`), 그리고 판정 조임 `ea38f5b` 유지(`22_structural_run.md:460`, 되돌릴 조건도 두지 않는다). 4절에 다시 올리면 결정권자는 같은 결정을 두 번 하고, 리포트는 진행이 아니라 되감기가 된다. 그 몰들의 문구가 바뀌었다면 할 일은 조임을 푸는 것이 아니라 문구를 고치는 것이고, 그것은 결정 요청이 아니라 작업이다.
- **남의 판정을 내 판정으로 바꿔 적지 않는다.** 코드·경계면 판정은 dev-qa(`18_devqa_report.md`), 콘텐츠·출처 판정은 verifier(`05_verification_report.md`)의 것이다. 리포트는 그 판정을 출처와 함께 옮긴다.

## 에러 핸들링

- 테스트를 돌릴 수 없다(playwright 없음·DB 없음·gradle 실패): 그 항목을 5절에 `확인: 미확인`으로 적고 이유를 한 줄 붙인다. 다른 테스트 결과로 대신하지 않는다.
- `git log` 범위가 애매하다(회차 시작 시각을 모른다): 마지막 리포트의 대장 행(`25_report_log.md`)에서 이어 붙이고, 그것도 없으면 사용자에게 기간을 확인한다. 임의로 "최근 며칠"을 잡지 않는다.
- 데이터 신선도가 층마다 다르다: 가장 오래된 값 하나로 뭉치지 않고 층을 나눠 적는다(가맹점 JSON · 온라인 카탈로그 항목별 · 코드 사본).
- `artifact-design` 을 부르지 못했다: 발간을 미루고 사용자에게 알린다. 디자인 판단 없이 발간하면 다음 회차부터 그 모양이 관례가 된다.
- 결정 요청 표의 "되돌리는 비용" 칸을 채울 수 없다: 그 항목은 4절이 아니라 3절(열려 있는 것)에 둔다. 되돌리는 길을 모르는 상태로 결정을 요구하지 않는다.

## 테스트 시나리오

- 정상 — 밤샘 회차 마무리:
  1. `git log --since` 로 그 회차의 커밋을 뽑아 과제 묶음으로 묶는다.
  2. 테스트를 직접 돌려 건수를 그 자리에서 적고, `23_backlog.md` 와 대조해 닫힌 것과 새로 열린 것을 가른다.
  3. 여섯 절 구조로 초안을 쓰고, 은어 표로 다시 쓴다.
  4. `artifact-design` 을 부른 뒤 스크래치패드에 `.html` 을 쓰고 `Artifact` 로 발간한다.
  5. 링크를 건네고 `25_report_log.md` 에 한 행을 남긴다.
- 정상 — 같은 리포트를 고쳐 다시 발간: 결정권자가 3절 한 항목의 사실관계를 정정해 달라고 한다. 스크래치패드의 **같은 파일**을 고치고 **같은 경로**로 `Artifact` 를 다시 부른다. 링크가 그대로 유지된 것을 확인하고 보고한다.
- 에러 — 테스트 일부 미실행: playwright 가 없어 렌더 검증이 종료 코드 2로 건너뛰어졌다. 5절에 "렌더 검증 미실행 · 사유: playwright 부재"로 적고, 3절에 "이번 회차의 렌더 회귀는 확인되지 않았다"를 남긴다. 정적 계약이 통과한 것을 렌더가 통과한 것으로 바꿔 적지 않는다.

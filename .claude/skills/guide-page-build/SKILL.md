# 가이드 페이지 구현 규약

`index.html` 하나로 완결되는 페이지를 만드는 규칙. 이 페이지는 **갱신을 전제로 존재**하므로, 갱신에 견디는 구조가 시각적 완성도보다 우선한다.

## 구조

- Vue 기반 단일 HTML. 외부 네트워크 없이 파일 하나로 열린다.
- 데이터는 `data/*.json`을 페이지에 주입한다. 파일 프로토콜(`file://`)에서는 `fetch`가 차단되므로 빌드 시점에 인라인으로 심는다.
- 폰트를 인라인 임베드하면 파일이 수 MB가 된다. 이 선택을 바꿀 때는 이유와 크기 변화를 리더에게 보고한다.

## 숫자를 손으로 쓰지 않는다

이 규약에서 가장 자주 위반되고, 위반의 대가가 가장 큰 규칙이다.

```
✕  <p>공식 안내 30곳 — 쇼핑 22 · 배달 8</p>
✓  <p>공식 안내 {{ activeCount }}곳 — 쇼핑 {{ shoppingCount }} · 배달 {{ deliveryCount }}</p>
```

하드코딩된 숫자는 데이터가 갱신되는 순간 거짓말이 된다. 그리고 아무도 눈치채지 못한다 — 표는 32행인데 헤더는 30곳이라고 말하고 있어도, 둘을 동시에 세어보는 사람이 없기 때문이다.

콘텐츠 명세의 **동적 문구 표**에 있는 자리는 전부 계산식으로 구현한다. 계산 대상은 `.claude/skills/onnuri-usage-data/references/data-schema.md`의 "파생 값" 절 참조:

| 자리 | 계산 |
|------|------|
| 총 개수 / 구분별 개수 | `status === 'active'` 필터 후 `kind`별 집계 |
| 표시용 연번 | 정렬 후 인덱스 |
| 업종 카운트 칩 | `verdict`별 집계 |
| 기준일 스탬프 | `min(items[].collected_on)` |

**기준일 스탬프를 상수로 두지 않는다.** 데이터를 갱신했는데 스탬프가 그대로면 이용자는 낡은 정보를 최신으로 믿는다.

## 데이터를 페이지에서 편집하지 않는다

목록이 틀렸으면 `data/*.json`을 고치고 다시 주입한다. 페이지 안의 배열을 직접 손대면 SSOT가 둘로 갈라지고, 다음 갱신에서 손댄 내용이 조용히 날아간다. 데이터 내용이 잘못되어 보이면 고치지 말고 `onnuri-data-curator`에게 알린다.

## 검색은 실패했을 때가 중요하다

이용자는 자기 동네 가게 이름으로 검색해본다. 그리고 아무것도 안 나온다 — 이 목록은 플랫폼 목록이지 점포 목록이 아니기 때문이다.

빈 결과 화면에서 해야 할 일:
1. 무엇으로 검색했는지 되짚어 준다 (`"{{ q }}"에 해당하는 항목이 없습니다`)
2. 초기화 경로를 준다
3. **다음 행동을 안내한다** — 개별 점포는 가맹점 지도에서 확인해야 한다는 것

3번이 빠지면 이용자는 "안 되는구나"로 잘못 결론 내린다. 빈 결과는 막다른 길이 아니라 분기점이다.

## 모바일에서 표가 살아 있어야 한다

이용자는 가게 안에서 휴대폰으로 본다.

- 좁은 화면에서는 카드형 배치로 전환하거나 표에 가로 스크롤을 준다
- **페이지 전체(body)는 절대 가로로 밀리지 않게 한다** — 표만 자기 컨테이너 안에서 스크롤된다
- 터치 영역은 충분히 크게. 필터 칩과 링크가 손가락으로 눌리는 크기여야 한다

## CSS 셀렉터는 의도한 요소만 맞힌다

**범용 단어 클래스(.card, .chip, .tag, .pay 류)를 후손 결합자로 선택하지 않는다.** 같은 단어가 다른 의미로 재사용되는 순간(컨테이너 `.card` vs 결제 태그 `.pay.card`) 후손 선택자는 둘 다 맞혀 엉뚱한 요소에 레이아웃 속성이 걸린다 — 실제 사고: `.result-list .card { min-height:420px }`가 결제 '카드' 태그에 적용되어 행 높이가 420px로 폭증했다. 규칙:

- 구조 컨테이너를 겨냥할 때는 **직계 결합자(`.result-list > .card`)** 또는 전용 클래스(`.list-card`)를 쓴다.
- 새 클래스를 지을 때 기존 클래스명과 부분 충돌하는지 grep으로 확인한다(`grep -c '"card\|card"' page.html`).
- 레이아웃 속성(min-height·overflow·position)을 넓은 셀렉터에 추가했다면, 그 셀렉터가 맞히는 **모든** 요소를 확인하고 나서 커밋한다 — 시각 결함은 문법 검사로 안 잡힌다. 렌더 스크린샷 또는 행 높이 같은 계측값으로 검증한다.
- **맨 요소 셀렉터(`table`·`td`·`th` 등)에 치수 속성을 걸지 않는다.** 페이지에 위젯·모달 등 다른 표가 들어오는 순간 전부 오염된다 — 실제 사고: `table { min-width:880px }`(결과 표용)가 챗 위젯 말풍선 표에 적용되어 880px로 삐져나갔다. 컨테이너 스코프(`.table-scroll table`)로 한정한다.

가능/조건부/불가를 색으로만 구분하면 색각 이상 이용자가 판별할 수 없다. 기호(✓ ! ✕)와 텍스트 라벨(`verdict_label`)을 항상 함께 렌더한다. 색은 보조 신호다.

## 조용한 실패를 만들지 않는다

- 데이터 파싱 실패 시 빈 배열로 넘어가 **빈 표를 렌더하지 않는다.** 빈 표는 "해당 사항 없음"으로 오해된다. 로드 실패를 화면에 드러내고 빌드를 멈춘 뒤 큐레이터에게 알린다.
- JS 콘솔 에러를 남긴 채 넘기지 않는다. 조용한 에러 하나가 표를 통째로 비운다.

## 재작업 시

기존 `index.html`을 먼저 읽는다. **통째로 다시 생성하지 않는다.** 기존 페이지에는 축적된 디자인 결정과 예외 처리가 들어 있고, 재생성은 그것을 조용히 삭제한다. 요청 범위에 해당하는 부분만 수정한다.
